Toys API Documentation

Toys Routes

Method Path Info Body
GET /toys Get all toys from the database. Returns 10 toys per page. Use ?skip=0 for the first page and ?skip=1 for the second page. No body
GET /toys/search?s=lego&skip=0 Search toys by name or info. The search is case insensitive. Returns 10 toys per page. No body
GET /toys/category/:catname Get toys by category name. Example: /toys/category/Lego Supports pagination using ?skip=0. No body
GET /toys/prices?min=50&max=200&skip=0 Get toys by price range. min is the minimum price. max is the maximum price. Supports pagination. No body
GET /toys/count Get the total number of toys in the database. No body
GET /toys/single/:id Get a single toy by its MongoDB ID. No body
POST /toys Add a new toy to the database. Requires a valid JWT token in the x-api-key header. The toy will belong to the logged-in user. 
{
  "name": "Lego Car",
  "info": "Lego racing car",
  "category": "Lego",
  "img_url": "",
  "price": 150
}
PUT /toys/:id Update an existing toy. Requires a valid JWT token in the x-api-key header. Users can update only their own toys. 
{
  "name": "Lego Car",
  "info": "Updated Lego racing car",
  "category": "Lego",
  "img_url": "",
  "price": 180
}
DELETE /toys/:id Delete a toy by ID. Requires a valid JWT token in the x-api-key header. Users can delete only their own toys. No body

Users Routes

Method Path Info Body
POST /users Register a new user. The password is encrypted using bcrypt before saving. 
{
  "name": "Arthur",
  "email": "arthur@example.com",
  "password": "123456"
}
POST /users/login Login with email and password. Returns a JWT token if the login is successful. 
{
  "email": "arthur@example.com",
  "password": "123456"
}

Authentication

POST, PUT and DELETE requests in the Toys API require authentication. After logging in, the user receives a JWT token. The token must be sent in the request headers.

Header Value
x-api-key JWT token received from /users/login
